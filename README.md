# Свинг-тренд v2 → Telegram (бесплатно, без подписки TradingView)

Этот бот раз в час сам забирает свечи с OKX напрямую с биржи — теперь сразу
для **ETH и BTC** — пересчитывает ту же логику, что и индикаторы
"Свинг-тренд v2" / "Свинг-тренд v2 [BTC]" в TradingView, и присылает
сообщение в Telegram, если появился новый сигнал (вход или выход) хотя бы по
одной из монет. Работает полностью бесплатно на GitHub Actions — твой
компьютер для этого включать не нужно.

## Файлы

- `okx_client.py` — получение исторических свечей с публичного API OKX
- `indicators.py` — базовые индикаторы (EMA, RMA/ATR, RSI, ADX/DMI), как в Pine
- `strategy.py` — сама логика сигналов + `ETH_PARAMS` и `BTC_PARAMS` (подтверждённые настройки под каждую монету)
- `telegram_bot.py` — отправка сообщения в Telegram
- `monitor.py` — главный скрипт: список `COINS` (какие монеты мониторить и с какими параметрами) + вся логика
- `.github/workflows/monitor.yml` — расписание (раз в час) на GitHub Actions
- `state_eth.json`, `state_btc.json` — создаются автоматически, хранят "последний обработанный бар" отдельно на каждую монету

## Как добавить ещё одну монету

Когда протестируешь и подтвердишь параметры новой монеты через Strategy
Tester (как делали для BTC): добавь в `strategy.py` новый `..._PARAMS` dict
(проще всего скопировать `BTC_PARAMS` и поменять то, что отличается), затем
в `monitor.py` в список `COINS` добавь ещё один `dict(inst_id="...-USDT-SWAP",
bar="1H", params=..._PARAMS, state_file=os.path.join(HERE, "state_....json"))`.
Больше ничего менять не нужно — цикл в `main()` сам обработает все монеты
из списка.

## Настройка (один раз)

1. Зайди на github.com, создай новый **приватный** репозиторий (например `swing-trend-bot`).
   Приватный — чтобы код и токен были видны только тебе.

2. Загрузи туда все файлы из этой папки (`tv_telegram_bot`), сохранив структуру
   папок как есть (важно: файл `.github/workflows/monitor.yml` должен остаться
   именно в папке `.github/workflows/` — GitHub находит расписания только там).
   Проще всего: на странице репозитория нажми "Add file" → "Upload files" и
   перетащи всё сразу (GitHub сам разложит по папкам, если в самом ZIP/структуре
   папки сохранены).

3. Добавь секреты (защищённые переменные, видны только тебе и работающему
   скрипту, никому больше): в репозитории зайди в
   **Settings → Secrets and variables → Actions → New repository secret**,
   и создай два секрета:
   - `TELEGRAM_BOT_TOKEN` — токен твоего бота от @BotFather
   - `TELEGRAM_CHAT_ID` — твой chat_id (см. как получить в переписке)

4. Зайди во вкладку **Actions** репозитория — GitHub может попросить один раз
   подтвердить, что workflow'ы разрешены ("I understand my workflows, go ahead
   and enable them").

5. Всё, дальше бот сам будет запускаться каждый час. Можно также запустить
   вручную сразу: вкладка Actions → workflow "Свинг-тренд мониторинг ->
   Telegram" → кнопка "Run workflow".

## Расчёт размера позиции в сообщении

Теперь при каждом сигнале входа (LONG/SHORT) бот сам считает и присылает:
размер позиции в USDT, количество монет, стоп в цифрах и %, убыток по стопу
в USDT и % от маржи, грубую цену ликвидации, справочную цель по R:R (только
ориентир — реально сделку ведёт трейлинг-стоп, не эта цена).

По умолчанию расчёт идёт от **100 USDT маржи на сделку и плеча x10** — как ты
и просил. Если захочешь поменять — в `Settings → Secrets and variables →
Actions → Variables` (не Secrets, эти значения не секретные) добавь
переменные `POSITION_MARGIN_USDT` и/или `POSITION_LEVERAGE` с нужными
числами, и пропиши их в `monitor.yml` в `env:` рядом с токенами (спроси меня,
если нужно — покажу как).

## Сканер пампов/дампов (отдельная система!)

Это ДРУГОЙ бот в этой же папке — `pump_monitor.py` + `pump_scanner.py`,
запускается своим расписанием `.github/workflows/pump_monitor.yml` (каждые
15 минут). Ищет резкие всплески объёма+цены по ВСЕМ USDT-перпетуалам OKX
(после отсечения совсем неликвидных пар), а не только по ETH/BTC.

**Важно понимать, чем это принципиально отличается от свинг-тренда:**
у свинг-тренда параметры подтверждены сотнями тестов через Strategy Tester
на реальной истории. У сканера пампов такой проверки в принципе быть не
может — состав "монет-кандидатов" каждый раз разный, среди них часто совсем
новые листинги без длинной истории торгов. Пороги в `pump_scanner.py`
(`PUMP_PARAMS`) — это разумная эвристика "объём в 3x выше среднего + цена
сдвинулась на 5%+ за 45 минут", а не бэктестированный рецепт. Относись к
сигналам как ко второму мнению, которое стоит проверить самому перед входом,
а не как к готовой системе с подтверждённым результатом.

Как это работает:
1. Раз в 15 минут забирает тикеры ВСЕХ перпетуалов OKX одним запросом,
   отсекает только пары с суточным оборотом ниже 3 млн USDT (совсем
   неликвидные — там выше риск манипуляции ценой и невозможности нормально
   выйти из позиции). Больше НИКАКОГО отсева нет — топ-N по 24ч-движению
   больше не используется как фильтр, чтобы не пропустить монету, которая
   не входит в топ по суточному изменению, но пампится/дампится именно
   сейчас (а такое бывает часто — движение началось недавно, а весь
   остальной день монета была плоская).
2. По КАЖДОЙ прошедшей фильтр ликвидности монете (обычно 150-250+
   инструментов) проверяет последние 15-минутные свечи параллельно (в
   несколько потоков разом, иначе не уложиться в 15 минут): объём всплеска
   ≥ 3x от среднего И движение цены ≥ 5% за последние 3 свечи (45 минут) —
   если оба условия сразу, это сигнал ПАМП (лонг) или ДАМП (шорт).
3. Совсем новые листинги (у которых ещё нет ~7-8 часов истории на 15м)
   просто пропускаются автоматически до тех пор, пока не накопят
   достаточно баров для расчёта ATR/среднего объёма — обычно это несколько
   часов после появления инструмента в списке перпетуалов OKX, дальше они
   участвуют в скане наравне со всеми.
4. Уже "открытые" (просигналенные) виртуальные сделки на каждом запуске
   подтягивают трейлинг-стоп (более тугой, чем у свинг-тренда — 1.5×ATR
   стоп, 2×ATR трейлинг, а не 2-2.5/4 — пампы разворачиваются намного резче
   обычного тренда) и шлют "ВЫХОД", когда стоп пробит.

Настройка — те же секреты `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`, ничего
дополнительно заводить не нужно. Просто добавь в репозиторий файлы
`pump_scanner.py`, `pump_monitor.py` и `.github/workflows/pump_monitor.yml`
(тот же способ — Edit/Add file на GitHub). Файл `pump_state.json` создастся
сам при первом запуске.

Что стоит знать перед тем, как реально торговать по этим сигналам:
- Многие свежие/маленькие монеты вообще не имеют перпетуального фьючерса на
  OKX сразу после листинга — сканер видит только то, что уже есть в списке
  перпетуалов OKX, а не вообще все новые токены на рынке.
- Расписание "раз в 15 минут" — не гарантия того, что GitHub Actions
  запустит именно в 15:00/15:15/15:30 и т.д. секунда в секунду: при высокой
  нагрузке на бесплатные раннеры GitHub запуск может задержаться на
  несколько минут. Для быстрого движения типа пампа это может означать вход
  чуть позже оптимального момента.
- На волатильных монетах убыток по стопу в % от маржи (см. блок "Позиция" в
  сообщении) может быть заметно больше, чем у ETH/BTC — обязательно смотри
  на это число и на предупреждение про близость ликвидации перед входом,
  возможно стоит уменьшать размер позиции именно для этих сигналов.

## Радар накопления (ищет монеты ДО пампа/дампа, не после)

Третий, отдельный бот — `accumulation_scanner.py` + `accumulation_monitor.py`,
расписание `.github/workflows/accumulation_monitor.yml` (раз в час). В
отличие от сканера пампов/дампов (который ловит движение, которое УЖЕ
началось), этот ищет признаки "накопления" ДО движения — по исследованиям
реальных пампов, схемы часто предваряются сжатием волатильности и ростом
объёма/открытого интереса на фоне узкого диапазона, до самого движения цены.

Используемые критерии (подробный разбор источников — в переписке):
- **Сжатие волатильности** — ширина полос Боллинджера ниже 25-го процентиля
  своей же истории. Сжатие само по себе НЕ говорит, в какую сторону будет
  движение — только что оно вероятно скоро случится.
- **Рост объёма на фоне сжатия** — отличает настоящее накопление от простого
  затишья на неликвиде.
- **Funding rate** — нейтральный/нейтральная зона на фоне сжатия считается
  более здоровым признаком (движение не на чужом перекошенном плече);
  экстремальный funding в любую сторону — риск сквиза именно туда.
- **Открытый интерес** — растёт ли он на фоне узкого диапазона (свой
  накапливаемый ряд, храним в `accumulation_state.json`, так как у OKX нет
  простого бесплатного эндпоинта истории OI).
- **Тренд BTC (4ч)** — просто контекст в каждом сообщении, не жёсткий фильтр:
  падающий BTC утягивает даже красивые альт-сетапы вниз.

**Важное противоречие, о котором нужно знать:** по исследованиям, реальные
цели пампов — почти всегда монеты с НИЗКОЙ ликвидностью (часто 24ч-объём
меньше 1 млн USDT), а это ровно то, что основной сканер пампов и свинг-бот
осторожно отсекают ради безопасности исполнения. Поэтому здесь два уровня:
"торгуемые" (порог 3 млн USDT, как у pump_scanner.py) и "только наблюдение"
(порог ниже, 300 тыс. USDT) — по второй группе НЕТ расчёта позиции в
сообщении, только явное предупреждение, что это повышенный риск
манипуляции/невозможности нормально выйти. Используй такие сигналы только
чтобы "посмотреть глазами", не для автоматического исполнения.

Каждый час бот шлёт:
1. Сводное сообщение "тест скана" — сколько всего инструментов, сколько
   прошло фильтр ликвидности, сколько реально попало в список наблюдения.
   Это и есть тот "тест-отчёт", который ты просил.
2. Отдельное сообщение по каждой НОВОЙ монете, попавшей в список наблюдения
   (без повтора на каждый час, пока она там же остаётся).

## Важно понимать

- **Первый запуск после этого обновления ничего не пришлёт по ОБЕИМ монетам**
  — это специально: старый `state.json` (был только для ETH) больше не
  используется, вместо него заводятся отдельные `state_eth.json` и
  `state_btc.json`. Каждый из них при первом запуске просто фиксирует
  текущий бар как точку отсчёта (без уведомления), а сигналы начнут
  приходить со СЛЕДУЮЩЕГО закрытого часового бара по каждой монете. Старый
  `state.json` можно просто удалить из репозитория — он больше не нужен.
- Логика на Python — это ручной перенос логики из Pine Script. Я проверил её
  на синтетических данных (нет ошибок в расчётах), но не могу подтвердить
  1-в-1 совпадение с TradingView без доступа к интернету из моей текущей
  среды. **Рекомендую первую неделю сверять сигналы бота с тем, что видно на
  графике в TradingView** — если разойдётся, пришли мне пример, поправлю.
- Секреты в GitHub никто, кроме владельца репозитория, не видит и не может
  прочитать даже в публичном логе workflow (GitHub автоматически маскирует их).
